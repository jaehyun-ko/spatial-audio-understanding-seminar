# 공간 오디오 세미나 디자인 시스템

학술 발표의 문제 장면, 논문 방법, 실험 근거를 읽는 데 필요한 조판 규칙과 사용법이다. 모든 장에서 하나의 밝은 테마를 사용한다. 짧은 청록색 선과 라벨을 공통 표식으로 두고, 그림의 판독과 비교 조건을 우선한다.

이 문서는 디자인의 구현 기준이다. 현재 덱은 본문 48장과 근거 부록 30장이고, 장 번호·역할은 [CAUSAL_DECK_ORDER.json](plans/CAUSAL_DECK_ORDER.json)을 따른다. 실제 렌더 검증 기록은 별도로 남긴다. `slides.md`는 발표 원고이며 `design-system.md`는 공통 레이아웃 회귀 검사용 10장 시편이다.

## 1. 적용 범위

- `slides.md`: 78장 발표 덱(본문 48 + 부록 30). `slides/part1.md`·`part2.md`·`part3.md`에서 조립한다. 37/29/12 파일 분할은 발표의 절 구분과 다르다. 새 연결 원고는 `slides/bridges/`에 둔다.
- `design-system.md`: 별도 10장 시편. 표지, 기초 개념, Manim 설명 애니메이션, AGG-RL Fig. 1 문제 그림, Neural-SRP 방법, AGG-RL Table 3 결과, 비교, 전환, SARL 그래프, 결론을 시험한다.
- `layouts/seminar.vue`: 새 `.seminar` 범위의 공통 프레임과 본문 변형.
- `layouts/seminar-cover.vue`, `layouts/seminar-section.vue`: 표지와 문제 전환용 레이아웃.
- `components/PaperFigure.vue`: 출처 그림과 캡션을 담는 컴포넌트.
- `components/ManimScene.vue`: 활성 슬라이드에서만 설명 영상을 재생하고 PDF에서는 포스터를 보여 주는 컴포넌트.
- `components/MathInline.vue`: `tex` 속성의 TeX 수식을 KaTeX로 조판하는 컴포넌트.

새 레이아웃의 그리드 규칙은 `.seminar`에만 적용한다. 전역 선택자로 기존 덱의 여백이나 그림 높이를 바꾸지 않는다. 논문 파일명을 조건으로 삼는 개별 CSS 예외도 만들지 않는다.

## 2. 기본 원칙

1. 한 화면에서 청중이 답할 질문을 하나 정한다. 문제·방법·결과의 역할을 혼동하지 않는다.
2. 그림은 읽어야 할 근거다. 본문을 크게 만든 뒤 그림을 남은 공간에 축소하는 방식을 피한다.
3. 논문의 전체 구조도와 전체 결과표를 한 화면에 함께 넣지 않는다. 필요한 부분과 한 가지 비교를 선택한다.
4. 중요한 실험 조건은 본문에서 읽을 수 있게 둔다. 인코더 고정 여부나 학습 데이터 조건을 작은 출처 문구에 숨기지 않는다.
5. 긴 글을 자동 축소하거나 `overflow: hidden`으로 가리는 것은 해결이 아니다. 제목·설명을 줄이거나 그림을 나누고 상세를 부록으로 옮긴다.
6. 원문 결과와 설명용 장면을 구별한다. 그림을 재구성했다면 재구성임을 표시하고 가상의 예시를 실제 모델 출력처럼 보이지 않게 한다.
7. 표지·절 전환·`focus` 개념 장·Manim 영상과 포스터를 포함한 78장 모두 `#f6f8fa` 캔버스를 사용한다. 레이아웃 변형은 배치와 설명 역할을 바꾸며 색상 테마를 바꾸지 않는다.
8. 청록색 라벨과 짧은 선은 읽기 시작점을 표시한다. 파란색은 입력, 현재 초점, 선택한 비교를 표시한다. 별도 대상이나 기하를 구별할 때는 짙은 청록색과 이름을 함께 사용한다.

### 3Blue1Brown에서 가져온 설명 방식

겉모양을 복제하지 않고 설명의 순서를 가져온다. 먼저 청중이 답을 궁금해할 질문을 보여주고, 구체적인 소리·배열·그래프에서 출발해 필요한 관계를 하나씩 더한다. 같은 대상은 다음 화면에서도 위치와 색을 유지한다. 식이나 모델 이름은 직관을 만든 뒤 제시한다.

- 개념 장: 질문 → 구체적인 예 → 달라지는 값 → 일반화의 순서로 구성한다.
- 방법 장: 입력과 현재 주목할 관계는 파랑, 별도 대상·기하는 짙은 청록으로 표시한다. 설명 라벨은 공통 청록색을 사용한다.
- 결과 장: 논문 수치와 축의 원래 의미를 유지한다. 선택한 행이나 셀에는 파랑 글자와 옅은 파랑 면을 적용한다. 이 강조는 성공 여부를 판정하지 않는다.
- 반례와 제한: 확인된 반례와 해석상 주의는 갈색 계열의 공통 색과 명시적인 문구로 표시한다.
- 영상식 전환을 흉내 내기 위해 한 장 안에 모든 단계를 넣지 않는다. 필요한 경우 같은 그림을 유지한 연속 슬라이드나 `v-click` 단계로 나눈다.

### 그림 중심 본문 — 2026-09-11 적용

현재 78장 덱에서는 설명을 장면·파형·좌표·특징·궤적·모듈의 시각적 관계로 먼저 보여준다. 긴 해설은 발표 노트에 둔다. 문장을 그대로 여러 상자에 옮기기보다 관측 가능한 차이를 그린다. 제목 → 그림의 직접 라벨 → 조건 캡션 → 한 문장 결론 → 출처의 위계를 공유한다.

정량 결과는 원문에 보고된 값을 축에 표시한 그래프를 사용한다. 기존 비교값 99개와 TWNM adapter 비교 보고값 3개의 출처·조건을 별도 원자료로 관리한다. 막대는 0 기준, 복수 지표는 독립된 축, 가까운 두 값은 위·아래 라벨로 배치한다. 현재 S73의 선 그래프는 50–60% 범위를 눈금으로 명시한다. 색은 비교 방법을 구별하며 성공·실패 판정이 아니다. `seminar-result-visual`, `seminar-chart-context`, `seminar-chart-note`로 공통 캡션 크기·간격을 유지한다. 표 조판 규칙은 디자인 회귀 시편과 향후 표가 필요한 경우에 적용한다.

Slidev/PDF에는 SVG, PPTX에는 대응 PNG를 사용한다. 그림 속 수식은 mathtext 또는 벡터 표기로 조판하고, 본문 TeX는 KaTeX로 조판한다. PNG로 들어간 개념도·그래프는 native PowerPoint 개체로 분해해 편집하는 대신 `scripts/visuals/`의 생성 코드와 `plans/RESULTS_VISUAL_DATA.json`·`plans/CAUSAL_ADAPTER_DATA.json`에서 수정하고 다시 생성한다.

### 보존·전달·사용을 연결하는 그림

현재 재구성에는 새 연결 페이지 14장과 설명 그림 13개가 포함된다. 공통 표기는 X → E(H) → P(Z) → LLM(답)이다. P는 projector/adapter이며 전처리와 구분한다. 인코더 판독, 자극 변화에 대한 표현 반응, token 기준선 비교, 답변의 입력 의존은 서로 다른 위치에 그린다. 논문의 구조적 설계와 실제 검증 결과를 구별하고, 다른 모델의 결과를 한 시스템의 검증 사다리로 연결하지 않는다.

같은 음원의 위치를 바꿀 때 의미 label의 유지와 위치 출력의 변화를 함께 보여준다. α는 +x에서 +y 방향, β는 xy면에서 +z 방향, r은 x축 위 두 마이크의 중점 O에서 음원까지의 거리다. 이 목표 정의를 두 마이크의 한 TDoA로 모든 좌표가 유일하게 복원된다는 주장으로 사용하지 않는다.

새 시험은 ‘제안’과 주황 점선으로 표시한다. 보고된 시험은 원문명·관측 위치를 함께 적는다. Spatial-Omni의 zero-spatial 비교를 적용 시점이 확인된 고정 checkpoint 제거로 그리지 않는다. SARL 판독을 LLM 사용으로, BMLD 거리 반응을 인간 역치로 표시하지 않는다. 근거와 제안의 상세 정의는 `plans/CAUSAL_CRITERIA.md`를 따른다.

주의 색을 경고 배경이나 ‘나쁜 모델’의 색으로 사용하지 않는다. 강조색도 우수함·인과성·정답을 자동으로 뜻하지 않는다. 색은 장식 팔레트가 아니라 같은 개념을 화면 사이에서 추적하는 표기다.

**색과 라벨을 함께 사용한다.** 기준선과 개입은 이름을 적고, 그래프에서는 필요하면 선 종류나 마커도 구별한다. 학습·고정 모듈 역시 색 외에 텍스트로 표시한다. `.seminar-label`은 의미 클래스와 관계없이 공통 청록색을 사용하며, `.semantic-negative` 라벨만 반례·주의 색을 사용한다.

원문 그림과 그래프의 색·범례·마커는 그대로 유지한다. 발표자가 만든 개념도와 설명 요소에는 공통 팔레트를 적용하되, 원문 범례를 발표 테마의 의미색으로 바꾸지 않는다.

기본 글꼴은 로컬 **Pretendard v1.3.9**다. PDF 출력의 글리프 경고를 줄이기 위해 가변 글꼴 대신 정적 WOFF2 네 굵기를 사용하고, CSS에서는 `Seminar Pretendard`라는 이름으로 연결한다.

- 글꼴 파일: `public/fonts/Pretendard-Regular.woff2`(400), `Pretendard-Medium.woff2`(500), `Pretendard-SemiBold.woff2`(600), `Pretendard-Bold.woff2`(700). 모두 `public/fonts/`에 둔다.
- 라이선스: `public/fonts/OFL-Pretendard.txt`
- 시스템 글꼴 폴백은 로딩 실패에 대비한 수단이다. 폴백으로 렌더된 상태를 정상 시편으로 간주하지 않는다.

일반 제목은 최대 두 줄, 캡션과 출처도 각각 최대 두 줄이다. 핵심 결론은 한 줄을 기본으로 한다. 숫자의 크기는 `.is-numeric`을 명시한 결과표 데이터 셀에 적용한다. 일반 문장과 조건 열은 해당 표의 본문 크기를 유지한다. 본문은 400, 라벨·행 제목은 600, 제목·선택한 주요 수치는 700 굵기를 사용한다.

## 4. 공통 프레임

기준 캔버스는 **1280×720**이다.

| 항목 | 기준 |
| --- | ---: |
| 왼쪽·오른쪽 여백 | 각각 72px |
| 위쪽 여백 | 48px |
| chapter 라벨 위치 | 상단 18px · 왼쪽 72px |
| 아래쪽 여백 | 28px |
| 내부 폭 | 1136px |
| 제목 영역 | 104px |
| 본문 영역 | 유동 높이, 기본 프레임에서 404px |
| 핵심 결론 영역 | 52px |
| 출처 영역 | 36px |
| 영역 사이 간격 | 16px |

높이의 기준식은 `48 + 104 + 16 + 404 + 16 + 52 + 16 + 36 + 28 = 720`이다. 출처는 `14px × 줄 높이 1.2 × 2줄`보다 넉넉한 36px를 확보한다. 본문의 그림과 캡션은 이 본문 영역 안에서 공간을 나눈다. 캡션을 추가하면서 그림 높이를 그대로 유지해 아래 영역을 침범하지 않는다.

chapter는 `.seminar-position`으로 절·질문 구역을 알리는 짧은 한 줄이며 17px/600, top 18px, left 72px를 사용한다. 제목 영역을 밀어 올리거나 본문과 같은 강조색·크기로 만들지 않는다. 본문의 절 라벨과 A–E 부록 라벨은 같은 규칙을 따른다.

제목·본문·결론·출처는 각자의 영역을 사용한다. 출처를 그림 위에 절대 위치로 겹치거나, 본문에 문장이 늘었다는 이유로 출처 위치를 임의로 옮기지 않는다. 두 줄 제목을 사용하더라도 같은 프레임 안에서 판독 가능성을 확인한다.

## 5. 레이아웃 선택

`seminar`의 `variant`는 다음 여섯 종류다.

| 변형 | 선택할 때 | 화면의 우선순위 |
| --- | --- | --- |
| `focus` | 기초 개념이나 하나의 관측 관계를 설명 | 현상과 핵심 관계. 짧은 설명이 그림을 보조 |
| `figure` | 문제의식 그림, 큰 그래프, 원문 그림 자체를 읽음 | 주그림과 캡션. 불필요한 설명 칼럼을 추가하지 않음 |
| `method` | 입력·출력과 중요한 설계 선택을 설명 | 필요한 구조 그림과 짧은 직접 주석 |
| `result` | 단일 실험 비교를 읽음 | 조건, 주표·주그래프, 해석의 순서 |
| `compare` | 방법이나 평가 계약의 차이를 비교 | 정렬된 표와 명시적인 비교축 |
| `closing` | 확인한 내용과 남은 조건을 정리 | 핵심 답과 해석 범위. 새 결과를 추가하지 않음 |

표지는 `seminar-cover`, 절의 문제 전환은 `seminar-section`을 사용한다. 두 구조 장도 공통 밝은 캔버스와 주 텍스트 색을 사용한다. 전환 장은 다음에 달라지는 질문이나 관측 조건을 보여준다. 논문 목록이나 내용 없는 구분 페이지를 반복하기 위한 용도로 사용하지 않는다.

### 본문 레이아웃 슬롯

| 슬롯 | 내용 |
| --- | --- |
| 기본 슬롯(`default`) | 제목 |
| `body` | 주그림, 결과표, 핵심 내용 |
| `aside` | 주그림을 해석하는 짧은 설명. 필요할 때만 사용 |
| `takeaway` | 이 화면이 남길 한 문장 |
| `source` | 원문, 그림·표 번호, 필요한 출처 표기 |

`aside`에 본문 전체를 다시 쓰지 않는다. 판단을 바꾸는 실험 조건은 `body` 또는 `aside`의 읽을 수 있는 크기로 표시하고, `source`에는 식별·귀속 정보를 둔다.

### 표지와 전환 슬롯

| 레이아웃 | 슬롯과 내용 |
| --- | --- |
| `seminar-cover` | `identity`: 소속·로고, 기본 슬롯(`default`): 제목, `subtitle`: 부제, `source`: 출처 |
| `seminar-section` | `context`: 절의 맥락, 기본 슬롯(`default`): 다음 질문, `bridge`: 앞 절과 이어지는 설명, `source`: 출처 |

표지와 전환은 공통 좌우 여백·출처 위치를 공유하되 본문용 104px 제목·404px 본문 프레임을 사용하지 않는다. 표지의 행 높이는 `64px / 유동 / 112px / 36px`, 전환은 `60px / 유동 / 112px / 36px`다. 이 두 레이아웃에는 `body`, `aside`, `takeaway` 슬롯을 넣지 않는다.

```md
---

# Neural-SRP의 쌍별 응답

::body::
<PaperFigure
  src="/research/neural-srp-architecture.svg"
  alt="마이크 쌍의 위상과 좌표로 위치 응답을 예측하고 합산하는 구조"
  caption="원문 방법 그림. 입력과 쌍별 합산 경로를 중심으로 읽는다."
/>

::aside::
위상 특징과 마이크 좌표, 방 크기를 사용한다.

후보 좌표는 학습 목표 구성에 사용한다.

::takeaway::
쌍별 위치 응답을 학습하고 합산한다.

::source::
Grinstein et al., Neural-SRP, arXiv:2403.09455v1, Fig. 3.
```

`PaperFigure`의 입력은 `src`, `alt`, `caption`이다. 일반 캡션은 `caption` 문자열 속성을 사용한다. 수식이나 별도 마크업이 필요한 캡션은 이름이 `caption`인 슬롯을 사용하며, 슬롯 내용이 문자열 속성보다 우선한다.

```vue
<PaperFigure src="/research/sarl-summary.svg" alt="SARL의 공간 요인별 판독 점수">
  <template #caption>
    방의 잔향 <MathInline tex="\mathrm{RT}_{60}" />와 부피·형상을 함께 읽는다.
  </template>
</PaperFigure>
```

캡션 문자열 안의 TeX 표기는 자동으로 조판되지 않는다. `MathInline`을 넣을 때는 반드시 슬롯을 사용한다. 기본 그림 배치는 `contain`이며 그림의 공간은 부모 그리드가 결정한다. 사용 위치마다 고정 높이를 덧붙여 프레임을 우회하지 않는다. 그림을 크롭해야 한다면 출처와 크롭 범위를 기록한 별도 자산을 준비한다.

### 수식

본문·표·라벨의 수식은 `<MathInline tex="..." />`로 작성한다. `tex`에는 TeX 본문만 전달하며 `$` 구분자는 넣지 않는다. 아래첨자·위첨자·분수·그리스 문자는 Unicode 조합이나 HTML `sub`·`sup` 대신 수식 조판을 사용한다.

```vue
<MathInline tex="\tau=\frac{\Delta\ell}{c}" />
<MathInline tex="\Delta\phi=2\pi f\tau" />
<MathInline tex="L=g_{\mathrm L}\cdot x" />
<MathInline tex="\eta_2=10^{-2}" />
<MathInline tex="L_{\mathrm{CL}}+L_{\mathrm{DOA}}" />
```

`MathInline`은 KaTeX의 HTML과 접근성용 MathML을 함께 출력하고, 잘못된 TeX는 오류로 처리한다. 수식은 주변 글자의 색과 크기를 따르며 한 표현식 안에서는 줄바꿈하지 않는다. 화면 검수에서는 수식 하나를 하나의 경계 상자로 확인한다. 숨겨진 MathML이나 분수·첨자의 개별 글자를 별도 본문 줄로 세지 않는다.

### 표가 필요한 경우의 작성 예시

```md
---
layout: seminar
variant: result
---

# 실제 녹음에 적응한 위치 추정

::body::
<table class="seminar-results">
  <caption>Recorded 4 조건의 위치 오차</caption>
  <colgroup>
    <col style="width: 56%" />
    <col style="width: 44%" />
  </colgroup>
  <thead>
    <tr><th scope="col">방법</th><th scope="col" class="is-numeric">위치 오차 (m) ↓</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">SRP</th><td class="is-numeric">1.19</td></tr>
    <tr class="is-emphasis"><th scope="row">NeuralSRP+</th><td class="is-numeric">0.77</td></tr>
  </tbody>
</table>

::aside::
NeuralSRP+는 실녹음 250개로 적응했다.

한 방의 정지 단일 음성 조건이다.

::takeaway::
이 적응·평가 조건에서 위치 오차가 줄었다.

::source::
Grinstein et al., Neural-SRP, arXiv:2403.09455v1, Table I.
```

결과표는 `seminar-results` 클래스를 단 native HTML 표로 작성한다. 수치 셀과 대응하는 열 헤더에 `.is-numeric`을 명시하면 오른쪽 정렬과 일정한 숫자 폭을 적용한다. 데이터 셀인 `td.is-numeric`은 38px이며, 열 헤더는 20px다. 둘째 열부터 일괄 수치로 취급하지 않는다. 관측 조건처럼 문장인 열에는 `.is-numeric`을 붙이지 않는다.

행이 많은 결과표는 `seminar-results seminar-results--dense`를 사용하며 수치 셀은 32px가 된다. 정성 비교표는 `seminar-comparison`, 내용이 많은 정성 비교표는 `seminar-comparison seminar-compact`를 사용하며 compact 본문은 22px다. Markdown의 정렬 표기만으로는 현재 CSS에서 같은 정렬을 보장할 수 없다. `colgroup`으로 열 폭을 정하고, 열 헤더는 `th scope="col"`, 행 제목은 `th scope="row"`로 구별한다.

`.is-emphasis`는 행 또는 개별 셀에 적용한다. 파랑 글자와 옅은 파랑 면은 이번에 읽을 비교를 표시한다. 성공·최고 성능·인과 효과를 자동으로 뜻하지 않는다. 지표별 결과가 섞이면 전체 행에 성과의 의미를 부여하지 않고 필요한 셀만 선택한다.

캡션은 표 안의 `<caption>`으로 두고 부모 표와 같은 폭 안에서 줄바꿈한다. 결과표와 비교표 모두 20px의 보조 텍스트 색을 사용한다. 표 뒤 해석은 `.seminar-table-note`로 작성한다. 수치는 편집 가능한 텍스트로 유지하고 단위와 좋은 방향을 헤더에 표시한다. 예시의 성과는 무적응 실환경 일반화의 근거로 확대하지 않는다.

## 7. 논문 그림의 원본과 편집성

1. 공식적으로 제공한 벡터 원본이 있으면 그것을 우선한다. 논문 PDF의 벡터 그림을 사용할 때에는 벡터를 유지한 추출본을 준비한다.
2. PDF에 픽셀 이미지로 들어간 그림은 `pdfimages`로 내장 원본을 추출한다. 화면 크기로 확대해 캡처한 이미지를 원본 대신 사용하지 않는다.
3. 브라우저·PDF 캡처는 배치와 판독을 확인하는 QA 용도다. 최종 그림 자산의 기본 취득 방법으로 삼지 않는다.
4. 전체 페이지가 아니라 필요한 그림·패널을 사용하되 축, 범례, 단위와 해석에 필요한 조건을 보존한다.
5. 출처와 버전, 그림·표 번호, 크롭·재구성 여부를 [ASSET_SOURCES.md](ASSET_SOURCES.md) 및 해당 근거 기록에 남긴다.

SVG라는 확장자만으로 텍스트 편집이 가능하다고 말하지 않는다. PDF에서 추출한 SVG가 글자를 윤곽선으로 바꾸었다면 확대 품질은 유지되지만 글꼴·문장을 직접 편집하기 어렵다. 이런 그림은 원문 자산으로 취급하고, 발표자가 붙이는 라벨과 캡션은 별도의 편집 가능한 텍스트로 둔다.

표와 간단한 결과 비교는 검증된 원문 수치로 재작성한다. 원문 분포 그림은 중앙값·IQR·오차 막대 등 의미를 보존한다. 곡선을 눈대중으로 읽어 새 수치를 만들거나 여러 지표를 하나의 점수로 합치지 않는다.

### PPTX 편집성과 수식

현재 PPTX에서는 제목·본문·일반 캡션·출처를 편집 가능한 native 텍스트로 보존한다. 도식 안 라벨과 정량 그래프는 대응 PNG에 포함되므로 PowerPoint에서 개별 수치나 도형을 직접 편집하는 개체가 아니다. SVG·생성 코드·원자료를 별도로 보존한다. 표가 있는 원고는 native 표로 내보낼 수 있지만 현재 그래프 페이지를 native 표라고 안내하지 않는다. `MathInline` 수식은 브라우저에서 조판한 모양을 보존한 고해상도 그림으로 내보낸다. 분수·첨자·기호를 평문으로 풀어 쓰지 않으며, 수식을 PowerPoint의 native 수식 객체라고 표시하지 않는다.

수식이 포함된 문장이나 표에서는 수식 부분을 그림으로 보존하고 주변 일반 텍스트와 표의 편집성을 유지한다. Manim의 수식은 `MathTex`로 만든 영상·포스터 안에 포함된다. 내보낸 PPTX에서는 수식의 선명도, 주변 문장과의 기준선, 표 셀 안의 위치를 실제 화면으로 확인한다.

### PDF 원본 추출 도구

`scripts/extract-pdf-figure.mjs`는 로컬 PDF에서 지정한 영역을 SVG로 추출하고 같은 이름의 `.source.json`에 원본·출력 해시, 페이지, 크롭 범위와 추출 정보를 기록한다. 원본 PDF를 수정하거나 `--source` URL에서 자동 다운로드하지 않는다. Poppler의 `pdfinfo`, `pdfimages`, `pdftocairo`가 필요하다.

```bash
node scripts/extract-pdf-figure.mjs --help
```

실제 AGG-RL Fig. 1의 `--pdf`, `--page`, `--box`, `--out`, `--source`를 지정한 재현 명령과 원본 주소는 [원본 추출 기록](ASSET_SOURCES.md#native-pdf-extraction)에 둔다. 페이지 번호는 1부터 시작하고, 크롭은 페이지 왼쪽 위 기준 PDF 포인트(1/72인치)다. 화면 픽셀 좌표와 혼용하지 않는다. 기존 SVG와 `.source.json`은 기본적으로 덮어쓰지 않으며, 두 파일의 교체가 필요할 때만 `--force`를 명시한다. 픽셀 원본은 별도로 `pdfimages -all`로 추출한다.

## 8. 밀도와 판독 게이트

다음 조건을 충족하지 못하면 내용을 덜어내거나 배치를 다시 선택한다.

- 일반 제목 두 줄, 캡션 두 줄, 출처 두 줄을 각각 넘기지 않는다. 결론 영역에는 짧은 한 문장을 둔다.
- 주그림 하나와 그 그림을 읽는 설명을 우선한다. 여러 전체 구조도나 전체 표를 병렬로 축소하지 않는다.
- 문제 장면에서는 바뀐 조건과 기대 출력이 구별되어야 한다. 방법 장에서는 학습·추론 경계와 핵심 입력을 읽을 수 있어야 한다.
- 결과 장에서는 비교 대상, 실험 조건, 단위, 좋은 방향을 확인할 수 있어야 한다. 조건이 다른 점수를 같은 실험처럼 정렬하지 않는다.
- 정성 비교표는 약 6행×4열 이내를 출발점으로 삼는다. 셀당 두 줄을 넘거나 숫자·단위를 읽기 어려우면 축을 줄이거나 나눈다.
- 핵심 그림 라벨은 1280×720 출력에서 별도로 판독한다. 주변의 20px 라벨과 비교해 지나치게 작다면 전체 그림 축소 대신 필요한 부분을 선택한다.
- 제목·본문·결론·출처가 서로 침범하지 않아야 한다. 부모가 내용을 잘라 보이지 않게 한 상태는 통과가 아니다.
- 색을 제거해도 대상과 조건을 구별할 수 있어야 한다. 색 외에 라벨·선 종류·마커 중 필요한 구분을 남긴다.

이 규칙의 목적은 모든 원문 글자를 본문 크기로 맞추는 것이 아니다. 발표 중 청중이 실제로 읽어야 할 글자와 관계를 선별하고 그 부분에 충분한 공간을 주는 것이다.

## 9. 실행과 검토

디자인 시편의 명령은 기존 덱과 분리한다.

```bash
npm run dev:design
npm run build:design
npm run export:design
npm run qa:design
npm run test:design
```

개발·검토 포트는 **3036**이다. `qa:design`과 `test:design`을 실행할 때에는 다른 터미널에서 `dev:design` 서버를 켜 둔다. `test:design`은 `node scripts/test-design-system.mjs --url http://localhost:3036`에 연결한다. `npm run dev`, `build`, `export`는 현재 78장 원고를 사용한다. 전체 검수 서버는 `npm run dev:final`의 3037이며 `npm run qa`로 확인한다. 실행 환경이나 브라우저 설치가 필요한 경우 프로젝트의 설치 안내를 따른다.

검토에서는 다음을 실제 화면으로 확인한다.

- 두 줄 제목과 긴 출처를 넣은 프레임의 충돌 여부.
- 세로 구조도, 넓은 문제 그림, 축이 많은 그래프의 서로 다른 비율.
- 원문 그래프의 작은 범례·단위, 수식의 아래첨자, 한글 줄바꿈.
- 로컬 글꼴 로딩과 PDF 출력에서의 문자 형태.
- 출처·조건·결론을 포함한 전체 화면의 판독 순서.
- 기본 화면과 축소 미리보기에서의 핵심 메시지 구분.
- 표지·전환·`focus`·Manim 영상과 포스터까지 동일한 밝은 배경을 사용하는지 여부.
- 표 캡션 20px, 라벨 20px, 결과 수치 38px·dense 32px와 의미색의 일관성.
- KaTeX 오류의 부재, 숨겨진 MathML 중복 제외, 분수·첨자를 포함한 수식의 실제 경계와 PPTX 선명도.

자동 점검이 오류를 보고하지 않아도 그림 안 글자의 판독이나 과학적 해석을 보장하지 않는다. 빌드·내보내기·QA를 실행했다는 사실과 실제 시편을 읽고 검토했다는 사실을 구별해 기록한다.

## 10. 본문 48장과 근거 부록 30장 제작 기준

[현재 장별 순서](plans/CAUSAL_DECK_ORDER.json)의 질문·역할·본문/부록 구분을 기준으로 레이아웃을 고른다. [발표 흐름](NARRATIVE_PLAN.md)과 [학술 구조](ACADEMIC_STRUCTURE.md)도 현재 본문 48장·부록 30장을 설명한다. 이전 구조 문서는 `plans/archive/`의 pre-causal 보존본에 남긴다. S48에서 본문을 마치며 S49 이후는 해당 질문의 조건·숫자·반례를 선택해 확인하는 근거 부록이다. 문제 그림·방법·결과의 역할을 바꾸어 빈 칸을 채우지 않는다.
