# 상세 제작 명세 2부: S38–S66

기준: 레드팀 수정 후의 78장 구성 중 중간 구간, 총 29장. 이 문서는 제작 지시서이며 실제 슬라이드나 확보한 새 그림을 뜻하지 않는다. 여섯 필드 전체를 화면에 옮기지 않는다. 화면에는 한 주장과 하나의 주근거를 남기고, 설명과 조건은 발표문·각주로 구분한다.

근거 ID: P12 BAT, P13 DSpAST, P14 OWL, P15 PhaseCoder, P16 Dual-BEATs, P17 Sci-Phi, P18 Spatial-Omni, P19 The World is Not Mono, P20 Motion 2025, P21 Dynamic QA 2026, P22 ST-AudioLM, P23 CoSTALA. C로 시작하는 ID는 발표자의 설명용 재구성이다. 방법 그림, 문제 장면, 실제 결과를 서로 대체하지 않는다. 원문 버전과 최종 표의 행·열은 근거 대장의 같은 P ID를 따른다.

## E. 질문 응답의 입력과 학습 설계

### S38. 같은 장면에 던지는 공간 질문

- 청중 질문: 음원의 종류와 위치를 출력하는 시스템에 언어 질문을 더하면 무엇을 새로 요구하는가?
- 남길 한 문장: BAT는 음원과 위치의 대응을 질문별 답변으로 읽는 공간 QA를 학습한다.
- 화면·근거: 문제 장면 C38, [P12 Table 1](https://arxiv.org/html/2402.01591v4). 동일한 소리 목록에서 알람과 말소리의 위치만 교환한 두 장면을 재구성한다. 입력 질문, 요구 출력, 학습한 질문 유형을 한 줄씩 대응시킨다.
- 설명 순서: “앞서 SELD도 사건과 위치를 연결했습니다. 여기서는 고정 출력에 더해, 특정 위치의 소리나 특정 소리의 위치를 질문하고 관계까지 답하게 합니다.”
- 경계·부록: binding을 LLM이 처음 도입했다고 말하지 않는다. 합성 단일·두 음원과 정해진 질문 유형을 자유로운 모든 공간 대화로 확대하지 않는다.
- 다음 연결: “이 질문들에 답할 때 실제 청각 입력이 얼마나 도움이 되었는지 보겠습니다.”

### S39. BAT의 청각 입력과 관계 QA

- 청중 질문: 질문 문장만 읽는 경우와 바이노럴 소리까지 듣는 경우의 답변이 얼마나 다른가?
- 남길 한 문장: BAT의 공간 관계 QA는 질문만 제공할 때보다 바이노럴 입력을 함께 줄 때 정확해진다.
- 화면·근거: 결과 [P12 Table 4](https://arxiv.org/html/2402.01591v4). 최종 BAT의 P와 B+P 두 행, Type E 평균 BA 54.48과 76.89를 주근거로 표시한다. 같은 합성 SpatialSoundQA의 Yes/No 평가라고 쓴다.
- 설명 순서: “인코더가 바이노럴 관측을 언어 입력으로 연결합니다. 이제 구조 이름보다 동일 모델의 청각 입력 유무를 비교하고, 질문만으로도 남는 점수를 함께 읽겠습니다.”
- 경계·부록: Fig. 1 구조와 C/D 제거 학습은 부록. mono 행은 one-stage 학습이므로 최종 모델과 입력만 다른 통제로 묶지 않는다.
- 다음 연결: “사건 이름과 방향·거리를 한 표현에서 읽을 때, 모두 같은 특징을 사용해야 할까요?”

### S40. 과제마다 다른 공간 특징의 역할

- 청중 질문: 소리를 구별하는 특징과 방향이나 거리를 판단하는 특징을 같은 비율로 섞어도 되는가?
- 남길 한 문장: DSpAST는 과제별 특징 선택을 위해 사건·방향·거리의 정보 경로를 나눈다.
- 화면·근거: 문제 재구성 C40, [P13 §3.2와 Fig. 1](https://arxiv.org/html/2509.13927v1). 하나의 관측에 사건·방향·거리 질문을 붙이고, 공통 특징 융합과 과제별 가중의 차이만 보여준다. 원문 Fig. 1은 방법 근거로 표기한다.
- 설명 순서: “사건 이름을 찾는 질문과 방향을 찾는 질문은 같은 관측을 다른 목적으로 읽습니다. 저자들은 이 차이를 특징 가중과 분기 설계에 반영했습니다.”
- 경계·부록: 세 독립 대형 인코더처럼 그리지 않는다. 공유 backbone과 과제별 부분을 구분하며 attention을 단서 사용의 인과 증거로 부르지 않는다.
- 다음 연결: “분기 설계를 적용한 표현이 실제 QA에서는 어떤 차이를 만들었을까요?”

### S41. DSpAST의 질문별 성능 변화

- 청중 질문: 표현을 바꾼 효과가 평균 점수 외에 목표 음원의 위치 질문에도 나타나는가?
- 남길 한 문장: 같은 single-stage BAT 설정에서 DSpAST는 방향·거리 질문과 관계 QA의 점수를 개선했다.
- 화면·근거: 결과 [P13 Table 3](https://arxiv.org/html/2509.13927v1). SpatialAST와 DSpAST의 single-stage 행만 비교한다. Type D 방향 정확도 34.80/37.35, DER 53.40/48.51, Type E 평균 BA 74.04/76.56을 별도 열로 둔다.
- 설명 순서: “질문의 목표 음원에 해당하는 방향과 거리를 먼저 읽겠습니다. 관계 평균도 개선되지만, 숫자는 각각 다른 출력과 지표를 평가합니다.”
- 경계·부록: 추가 특징·curriculum·loss도 변경했다. 분기 하나의 인과효과로 단정하지 않는다. Table 2 ablation은 부록이며 원 BAT 논문의 수치와 직접 연결하지 않는다.
- 다음 연결: “이번에는 특징 분기와 다른 선택으로, 공간 표현의 학습 지도 자체를 살펴보겠습니다.”

### S42. 음향 표현을 위한 기하적 학습 지도

- 청중 질문: 소리의 방향과 거리를 학습할 때 방의 기하 정보를 지도 신호로 사용할 수 있는가?
- 남길 한 문장: OWL의 SAGE는 학습 시 음향 관측과 방의 기하 정보를 함께 이용한다.
- 화면·근거: 문제 장면 [P14 Fig. 2](https://arxiv.org/html/2509.26140v1). BiDepth의 청취자 관측과 panoramic depth 대응을 중심으로 원문 그림을 배치한다. 깊이와 RIR은 학습 지도, 바이노럴은 추론 관측이라고 구분한다.
- 설명 순서: “같은 소리도 방과 전파 경로에 따라 달라집니다. 이 연구는 학습 장면에서 알고 있는 기하 정보를 사용해 음향 표현을 지도할 수 있는지 묻습니다.”
- 경계·부록: 깊이 영상을 추론 때도 넣는 시청각 모델로 소개하지 않는다. 합성 기하의 지도 효과와 실제 방에 대한 일반화를 분리한다.
- 다음 연결: “기하 정보가 어떤 학습 경로를 통해 바이노럴 표현에 영향을 주는지 보겠습니다.”

### S43. SAGE의 보조 학습과 OWL의 추론 입력

- 청중 질문: 학습 때 사용한 깊이와 RIR 없이도 공간 질문에 답하도록 어떻게 구성하는가?
- 남길 한 문장: SAGE의 기하 보조 학습을 거친 음향 인코더만 OWL의 추론 경로에 남는다.
- 화면·근거: 방법 [P14 Fig. 4](https://arxiv.org/html/2509.26140v1). 깊이와 음향 특징의 RIR 복원 경로를 학습 구역에 둔다. 바이노럴 인코더, projector, 언어 모델의 추론 경로를 원문 배치 안에서 구분한다.
- 설명 순서: “학습에서는 RIR 복원 오차가 음향 표현에도 영향을 줍니다. 질문에 답할 때는 음향 인코더가 만든 표현을 언어 모델에 전달합니다.”
- 경계·부록: OWL QA 학습에서는 음향 인코더를 고정한다. Q-Former 상세와 CoT curriculum은 부록으로 보내고, 구조만으로 기하 이해의 성공을 주장하지 않는다.
- 다음 연결: “같은 데이터에서 기하 학습 항을 바꾼 실험으로 그 효과를 확인하겠습니다.”

### S44. 기하 학습 항과 공간 예측 오차

- 청중 질문: 전체 시스템 비교를 넘어 기하 지도 항의 효과를 직접 확인할 수 있는가?
- 남길 한 문장: BiDepth에서 기하 학습 항을 포함한 SAGE는 방향과 거리 예측 오차를 줄였다.
- 화면·근거: 결과 [P14 Table 5](https://arxiv.org/html/2509.26140v1). binaural-only loss와 전체 geometric loss의 두 행을 고른다. MAE 26.32°/21.67°, DER 17.11/14.32를 표시하고 낮을수록 좋음을 풀어 쓴다.
- 설명 순서: “여기서는 다른 LLM과의 순위를 보지 않고 학습 항을 비교합니다. 방향과 거리 오차가 함께 줄어든 범위까지 기하 지도의 효과를 읽겠습니다.”
- 경계·부록: QA 전체 시스템은 Table 4의 부록 근거다. CoT나 projector의 효과와 혼합하지 않으며, 모든 데이터셋·지표에서 우세하다고 말하지 않는다.
- 다음 연결: “다른 문제로 옮겨, 기존 의미 인코더가 작은 좌우 크기 차이를 보존하는지 살펴보겠습니다.”

### S45. 작은 좌우 레벨 차이와 의미 인코더

- 청중 질문: 같은 소리의 좌우 크기만 조금 달라져도 의미 인코더로 그 차이를 읽을 수 있는가?
- 남길 한 문장: Dual-BEATs는 amplitude-panned stereo에서 작은 채널 레벨 차이를 읽는 문제를 다룬다.
- 화면·근거: 문제 재구성 C45, [P16 §3.2](https://arxiv.org/html/2607.08800v1). 같은 모노 소리에 서로 다른 좌우 gain을 적용하는 조건을 보여준다. 목표 출력은 Left/Center/Right이고, 방·마이크·HRTF 그림은 넣지 않는다.
- 설명 순서: “이번에는 방의 기하를 추정하지 않고 입력을 제한하겠습니다. 소리 내용은 유지하면서 채널 크기 차이를 바꾸면, 정규화를 거친 표현에 무엇이 남는지 물을 수 있습니다.”
- 경계·부록: 원문 Fig. 1은 방법 그림이다. amplitude panning을 실제 방향 변화나 배열 일반화와 동일시하지 않는다.
- 다음 연결: “작은 독립 잡음을 더하는 dither 조건이 이 제한된 판단을 어떻게 바꾸는지 보겠습니다.”

### S46. Dither 조건과 stereo 방향 분류

- 청중 질문: 같은 레벨 차이 조건에서 독립 dither의 유무가 분류 결과를 바꾸는가?
- 남길 한 문장: Dual-BEATs의 dither 효과는 panning 크기와 언어 모델 조건에 따라 달라진다.
- 화면·근거: 결과 [P16 Table 1](https://arxiv.org/html/2607.08800v1). OLMo-3-7B, Direction-First, PA=0.50의 Off 37.9와 On 97.1을 중심으로 표시한다. 동일 행의 PA=0.00도 함께 두어 조건 의존성을 남긴다.
- 설명 순서: “좌우 채널은 고정 BEATs를 각각 통과합니다. 여기서는 DA=0.05의 독립 dither 유무를 비교하며, 큰 차이와 작은 차이에서 결과를 따로 읽겠습니다.”
- 경계·부록: zero-shot은 미관측 panning 조건이다. 초록 97.2 대신 표의 97.1을 사용한다. 실제 잡음 강건성과 새 HRTF 성능은 주장하지 않는다.
- 다음 연결: “레벨 조건을 바꾸는 문제와 구별해서, 마이크 배열 자체가 달라지는 문제로 돌아가겠습니다.”

### S47. 마이크 좌표를 받는 공간 언어 입력

- 청중 질문: 마이크 수와 배치가 달라지는 신호를 언어 모델에 어떻게 연결할 수 있는가?
- 남길 한 문장: PhaseCoder는 다채널 오디오와 마이크 좌표로 공간 표현을 만들고 기존 의미 경로와 결합한다.
- 화면·근거: 문제 관측 [P15 Fig. 2](https://arxiv.org/html/2601.21124v2). 채널 사이 위상 차이를 읽는 부분을 중심으로 사용한다. 입력에 마이크 좌표가 필요하다는 문장을 붙이고, Fig. 1·3의 전체 방법은 부록에 둔다.
- 설명 순서: “같은 방향도 배열 배치에 따라 다른 채널 관계를 만듭니다. 이 모델은 좌표를 함께 받아 공간 표현을 만들며, 말의 내용은 기존 의미 입력 경로로 읽습니다.”
- 경계·부록: geometry-agnostic을 좌표 불필요로 번역하지 않는다. 자유 공간의 무지향 마이크 가정과 장치 산란 효과를 구분한다.
- 다음 연결: “배열 입력을 다루는 능력과 언어 질문을 푸는 능력을 분리해서 평가하겠습니다.”

### S48. PhaseCoder의 공간 QA와 남는 오류

- 청중 질문: 공간 표현을 Gemma에 결합하면 관계 질문과 목표 발화 선택이 함께 개선되는가?
- 남길 한 문장: PhaseCoder의 공간 토큰은 관계 QA를 개선하지만 전사 성능까지 일괄 개선하지는 않는다.
- 화면·근거: 결과 [P15 v2 Table 3](https://arxiv.org/html/2601.21124v2). Gemma baseline/SFT의 Task 2를 synthetic 48.44/76.76, RSL2019 53.91/73.83으로 나란히 둔다. 다른 지표를 한 평균으로 합치지 않는다.
- 설명 순서: “두 조건의 관계 정확도는 높아집니다. 다만 RSL targeted WER는 42.90에서 48.41로 악화하므로 전사 개선까지 묶어 말할 수 없습니다.”
- 경계·부록: baseline은 mono이고 SFT에는 공간 입력과 추가 학습이 함께 들어간다. 비중첩 연결, RSL train split 사용, WER 필터링을 명시한다. 실녹음 DOA Table 1은 부록이다.
- 다음 연결: “지금까지 서로 다른 성공 조건을 비교했으므로 입력과 학습의 차이를 한 번 정리하겠습니다.”

### S49. 입력·전처리·학습 범위의 비교

- 청중 질문: 모두 공간 오디오 모델이라는 이유만으로 같은 조건의 성능처럼 비교해도 되는가?
- 남길 한 문장: 공간 모델의 결과를 비교하려면 입력 형식과 추론에 필요한 정보, 학습 범위를 함께 읽어야 한다.
- 화면·근거: 비교표 C49, P12–P16의 방법을 종합한다. 행은 BAT/DSpAST/OWL/Dual-BEATs/PhaseCoder, 열은 오디오 형식·전처리·추론 메타데이터·학습 결합이다. 각 셀에는 핵심 조건 하나만 적고 순위나 점수를 넣지 않는다.
- 설명 순서: “OWL의 깊이는 학습 지도이고 PhaseCoder의 좌표는 추론 입력입니다. Dual-BEATs는 panning 합성이므로 각 연구의 일반화라는 말이 가리키는 대상을 구별해야 합니다.”
- 경계·부록: FOA를 임의의 네 마이크 파형으로 바꾸지 않는다. 모든 인코더가 고정이거나 모든 언어 연결이 같은 학습이라고 요약하지 않는다.
- 다음 연결: “이제 한 질문의 답을 넘어 여러 음원의 속성을 함께 기술하는 출력을 보겠습니다.”

## F. 다중 음원의 기술과 관계 판단

### S50. 여러 음원과 환경을 함께 기술하는 출력

- 청중 질문: 여러 소리가 있는 장면을 하나의 답변으로 기술하려면 어떤 정보를 유지해야 하는가?
- 남길 한 문장: Sci-Phi는 각 음원의 속성과 배경·방 특성을 한 장면 설명으로 출력한다.
- 화면·근거: 문제 재구성 C50, [P17 §3.3](https://arxiv.org/html/2510.05542v1). 방향성 음원별 항목과 방·배경 항목을 구분한 장면–출력 예시를 쓴다. 실제 생성 답변이 아닌 출력 형식의 설명임을 표시한다.
- 설명 순서: “한 방향을 답하는 대신 장면 전체를 기술하도록 요구하겠습니다. 각 소리의 내용과 공간 속성이 같은 음원에 붙어 있어야 설명이 일관됩니다.”
- 경계·부록: 최대 네 방향성 음원의 학습 범위를 남긴다. 방·배경의 추정치를 관측된 사실처럼 읽지 않으며, 자유로운 모든 장면 묘사를 검증했다고 말하지 않는다.
- 다음 연결: “이런 출력을 위해 의미와 공간 관측을 어떤 경로로 함께 전달할까요?”

### S51. Sci-Phi의 공간 경로와 의미 경로

- 청중 질문: 소리의 내용과 공간 속성을 함께 출력하려면 기존 오디오 언어 모델을 어디에서 확장하는가?
- 남길 한 문장: Sci-Phi는 FOA 공간 특징과 W 채널 의미 특징을 별도 경로로 언어 모델에 전달한다.
- 화면·근거: 방법 [P17 Fig. 1](https://arxiv.org/html/2510.05542v1). 공간 인코더와 기존 모노 인코더의 입력·결합을 중심으로 읽는다. 학습되는 공간 경로와 고정된 기존 의미 경로를 원문의 기호로 구분한다.
- 설명 순서: “공간 경로는 FOA 특징을 읽고 의미 경로는 W 채널을 읽습니다. 장면 metadata를 답변으로 학습하면서 어떤 부분을 조정하는지 그림에서 확인하겠습니다.”
- 경계·부록: frozen 의미 인코더만으로 모든 언어 능력 보존이 입증되지는 않는다. LoRA 설정과 세부 출력 토큰은 부록으로 보낸다.
- 다음 연결: “속성들을 많이 출력했다면, 그것들이 같은 음원에 맞게 연결됐는지를 평가해야 합니다.”

### S52. Sci-Phi의 음원별 장면 기술 성능

- 청중 질문: 음원 이름과 위치를 각각 잘 맞혔어도 둘의 대응이 틀리면 높은 점수를 받아도 되는가?
- 남길 한 문장: Sci-Phi는 음원 단위의 대응을 유지하는 TupleScore로 장면 기술의 성능을 비교한다.
- 화면·근거: 결과 [P17 Fig. 2의 TupleScore 패널](https://arxiv.org/html/2510.05542v1). finetuned SELDNet+Phi-4와 Sci-Phi를 비교한다. synthetic-RIR와 real-RIR 조건을 분리하고 1–4음원 평균을 나타내는 diamond만 남긴다.
- 설명 순서: “이름과 방향을 서로 바꿔 붙인 작은 예로 공동 채점의 필요성을 설명하겠습니다. 그 원칙으로 읽은 두 시스템의 점수를 같은 RIR 조건 안에서 비교합니다.”
- 경계·부록: Table 2의 OS/OM은 채점 원칙이며 모델 ablation이 아니다. 실측 RIR 합성을 현장 혼합음 녹음으로 부르지 않고 전체 지표는 부록에 둔다.
- 다음 연결: “전체 기술과 다른 인터페이스로, 특정 음원이나 관계를 묻는 질문을 나누어 보겠습니다.”

### S53. 개별 속성과 음원 사이의 관계

- 청중 질문: 위치를 추정하는 질문과 그 위치의 음원을 고르거나 다른 음원과 비교하는 질문은 어떻게 다른가?
- 남길 한 문장: Spatial-Omni의 과제 구분은 공간 예측과 음원 식별·관계 판단을 별도로 평가하게 한다.
- 화면·근거: 문제 예시 [P18 v2 Fig. 2(a)](https://arxiv.org/html/2606.10738v2). 위치로 음원 찾기 IS-Loc과 상대 좌우 RLR의 원문 사례를 선택해 한 장면 안에 대응시킨다. 전체 과제 목록은 작은 글씨로 채우지 않는다.
- 설명 순서: “위치를 알고 소리 이름을 고르는 질문과 두 소리의 좌우 관계를 비교하는 질문을 보겠습니다. 어떤 출력이 정답인지 먼저 정한 뒤 모델을 설명하겠습니다.”
- 경계·부록: 질문의 문장 길이가 추론 깊이를 뜻하지 않는다. 서로 다른 답변 형식과 채점 방법을 하나의 보편적 정확도로 취급하지 않는다.
- 다음 연결: “이 질문들에 공간 정보를 제공하는 FOA 경로를 살펴보겠습니다.”

### S54. Spatial-Omni의 공간 토큰 결합

- 청중 질문: 기존 의미 오디오 입력을 유지하면서 공간 정보를 언어 모델에 더할 수 있는가?
- 남길 한 문장: Spatial-Omni는 FOA에서 만든 공간 토큰을 기존 의미 오디오 입력에 결합한다.
- 화면·근거: 방법 [P18 v2 Fig. 1](https://arxiv.org/html/2606.10738v2). FOA 인코더와 공간 토큰 결합점을 중심으로 원문 구조를 읽는다. 의미 경로와 공간 경로의 입력 차이를 표시하고 학습 단계는 짧은 설명으로 덧붙인다.
- 설명 순서: “기존 의미 경로 옆에 공간 경로를 둡니다. projector 정렬과 언어 적응 뒤에 공간 인코더의 학습 가능한 부분도 조정한다는 점을 구분하겠습니다.”
- 경계·부록: 의미 경로의 구조적 보존과 일반 오디오 성능 보존은 다른 주장이다. 후자는 Fig. 5의 별도 결과가 필요하며 모델 크기 비교는 부록으로 보낸다.
- 다음 연결: “앞서 본 위치 기반 식별과 좌우 관계 질문으로 다시 돌아가겠습니다.”

### S55. 공간 토큰이 있는 조건과 없는 조건

- 청중 질문: 같은 Spatial-Omni 계열에서 공간 토큰을 없애면 식별과 관계 판단은 어떻게 달라지는가?
- 남길 한 문장: SO-7B의 실제 공간 토큰 조건은 zero-spatial 조건보다 위치 추정과 식별·관계 점수가 높다.
- 화면·근거: 결과 [P18 v2 Table 2](https://arxiv.org/html/2606.10738v2). SO-7B-zs/SO-7B의 EAzi 13.06/76.38, IS-Loc 40.69/66.81, RLR 47.15/72.97을 표시한다. 허용오차 기반 각도 추정, 위치 기반 음원 식별, 상대 좌우 판정이라는 지표 정의를 각 열에 남긴다.
- 설명 순서: “외부 모델 순위 대신 공간 입력을 바꾼 내부 비교를 읽겠습니다. 각도 추정에서 시작해 앞서 본 위치 기반 식별과 좌우 관계로 연결하겠습니다.”
- 경계·부록: 특정 위상 단서의 인과효과로 확대하지 않는다. MIX 결과와 일반 음향 보존은 별도 부록이며, SC의 WER는 다른 지표와 좋은 방향이 다르다.
- 다음 연결: “관계 질문을 더 복합적인 장면 선택과 구별해 정의한 연구를 보겠습니다.”

### S56. 지각·음원 결합·복합 질의

- 청중 질문: 음원의 개별 속성을 아는 것과 그 속성을 묶어 복합 질문에 답하는 것은 어떻게 다른가?
- 남길 한 문장: TWNM은 원자적 지각, 관계 연결, 복합 질의를 서로 다른 평가 층위로 정의한다.
- 화면·근거: 문제 예시 [P19 v3 Fig. 4](https://arxiv.org/html/2601.02954v3). 같은 청취자 기준의 장면에서 L1/L2/L3 질문을 순서대로 드러낸다. Fig. 1의 추상 계층은 부록으로 보내고 실제 질문의 요구를 먼저 읽는다.
- 설명 순서: “음원의 속성을 고르는 질문에서 시작해 그 속성이 어느 음원에 속하는지 연결하겠습니다. 마지막 질문은 연결한 정보로 추가 선택을 요구합니다.”
- 경계·부록: 예시 그림은 모델 입력이 아니다. 숨겨진 scene metadata는 정답 생성에만 쓰며, L3 점수를 모두 순수 공간 추론 능력으로 해석하지 않는다.
- 다음 연결: “이 구분을 학습 데이터와 모델 결합에 어떻게 반영했는지 보겠습니다.”

### S57. TWNM의 음원별 공간 표현과 학습

- 청중 질문: 여러 음원의 정보가 섞인 관측을 언어 모델에 어떤 단위로 전달하는가?
- 남길 한 문장: TWNM은 음원별 공간 표현과 W 채널 의미 표현을 결합하고 단계별로 언어 출력을 학습한다.
- 화면·근거: 방법 [P19 v3 Fig. 2](https://arxiv.org/html/2601.02954v3). FOA spatial encoder의 source slots와 의미 경로가 만나는 부분을 중심으로 보여준다. projector 정렬, SFT, SAPO는 실제 학습 순서로 표시한다.
- 설명 순서: “음원별 공간 정보를 먼저 정리하고 의미 표현과 함께 언어 모델에 전달합니다. 다음 장에서는 최종 SAPO가 어떤 질문의 점수를 바꿨는지 확인하겠습니다.”
- 경계·부록: v3의 FOA·SAPO를 초기 binaural·GRPO와 섞지 않는다. 과제 정의의 객체·관계 기호를 모델이 명시적 scene graph로 출력한다고 설명하지 않는다.
- 다음 연결: “복합 질문의 개선이 기초 지각과 관계 연결에도 동일하게 나타나는지 보겠습니다.”

### S58. SAPO 이후의 과제별 변화

- 청중 질문: 최종 추론 학습 단계는 모든 평가 층위의 점수를 동시에 높이는가?
- 남길 한 문장: TWNM의 SAPO는 복합 질의 점수를 크게 높였지만 L1과 L2는 소폭 낮아졌다.
- 화면·근거: 결과 [P19 v3 Table 5](https://arxiv.org/html/2601.02954v3). SFT/SAPO의 L1 65.19/63.64, L2 70.61/69.89, L3 51.19/79.76을 나란히 제시한다. exact MCQA와 단일 실행 결과라는 조건을 붙인다.
- 설명 순서: “먼저 큰 변화가 나타난 L3를 읽겠습니다. 다음으로 앞의 두 열을 돌아보면, 전체 평균 상승이 모든 능력의 동시 상승을 뜻하지 않음을 확인할 수 있습니다.”
- 경계·부록: dry-clip identity 중복과 STARSS23 recording overlap을 부록에 명시한다. 채점 방식이 다른 corrupted-input 통제를 같은 효과 크기로 합치지 않는다.
- 다음 연결: “지금까지의 장면 질문에 시간 변화가 들어오면, 서로 다른 종류의 정보가 필요합니다.”

## G. 사건 순서·움직임·질의 구간

### S59. 시간 정보를 요구하는 세 가지 질문

- 청중 질문: 시간 이해라는 말은 사건의 순서, 음원의 이동, 질문에 필요한 구간 중 무엇을 가리키는가?
- 남길 한 문장: 사건 순서와 연속 이동, 질문 관련 구간은 서로 다른 시간 정보의 요구다.
- 화면·근거: 문제 재구성 C59, [P20 Table 1](https://arxiv.org/html/2509.14666v1)과 [P21 Table 2](https://arxiv.org/html/2602.16334v1). 하나의 시간축에서 사건 발생과 위치 변화를 분리하고, 질문이 가리키는 구간을 표시한다. 실제 예측 궤적으로 제시하지 않는다.
- 설명 순서: “알람이 먼저 울렸는지, 알람이 이동했는지, 어느 구간의 알람을 묻는지는 서로 다른 질문입니다. 뒤의 연구들도 이 구분에 맞춰 읽겠습니다.”
- 경계·부록: 세 축을 성능 순위나 발전 단계로 만들지 않는다. 순서가 있는 두 사건을 이동하는 단일 음원으로 그리지 않는다.
- 다음 연결: “먼저 시간별 공간 속성을 읽어 추론 모델에 전달하는 방식을 보겠습니다.”

### S60. 예측한 움직임 속성으로 질문에 답하기

- 청중 질문: 오디오를 직접 언어 모델에 넣지 않고 시간별 예측 속성으로 움직임 질문을 풀 수 있는가?
- 남길 한 문장: Motion 2025는 학습한 지각 결과를 구조화해 추론 모델에 전달하는 경로를 평가한다.
- 화면·근거: 결과 [P20 Table 3](https://arxiv.org/html/2509.14666v1). DSAST+Qwen7B/DSASTwAGM+Qwen7B의 Overall 20.7/31.1과 DoA 35.8/26.4를 선택한다. JSON으로 예측 속성을 전달한다는 방법은 짧게 설명하고 Fig. 1 전체는 부록에 둔다.
- 설명 순서: “언어 모델은 지각 모듈의 시간별 예측을 읽습니다. AGM을 결합하면 전체 점수는 높아지지만 방향 질문 점수는 낮아져, 모든 움직임 질문의 개선은 아닙니다.”
- 경계·부록: training-free는 추론 LLM 연결의 추가 학습에 관한 말이다. 지각 인코더 자체를 무학습으로 부르거나 oracle 속성 결과와 혼합하지 않는다.
- 다음 연결: “여러 소리 중 질문과 관련된 구간을 더 잘 골라주면 답도 달라질까요?”

### S61. 질문 관련 구간 선택과 reasoning 설정

- 청중 질문: 시간 구간 선택의 효과와 언어 모델의 thinking 효과를 어떻게 구별하는가?
- 남길 한 문장: Dynamic QA는 masking과 thinking 조건을 나누어 질문별 개선을 평가한다.
- 화면·근거: 결과 [P21 Table 3](https://arxiv.org/html/2602.16334v1). Overall 행의 NoMask/AGM/GT를 선택한다. Thinking은 54.3/55.0/56.1, Non-Thinking은 54.1/54.0/54.1이다. GT는 정답 구간을 제공하는 참고 조건으로 표시한다.
- 설명 순서: “먼저 thinking 설정을 고정한 채 구간 선택을 비교하겠습니다. 이후 같은 mask에서 thinking 설정을 비교하면 어느 변경의 효과인지 구분하기 쉽습니다.”
- 경계·부록: GT mask는 실제 시스템이 아는 정보가 아니다. 큰 하위 과제 개선량을 전체 성능 개선으로 바꾸지 않으며 합성 이동 장면의 범위를 남긴다.
- 다음 연결: “구간을 골라 전달하는 설계와 달리, 시간별 공간 표현을 언어 모델과 연결하는 방식을 보겠습니다.”

### S62. 음원 정체성과 시간별 위치의 대응

- 청중 질문: 두 음원이 움직일 때 특정 소리의 이전 위치와 이후 위치를 연결해 답할 수 있는가?
- 남길 한 문장: ST-AudioLM의 과제는 음원 정체성과 시간별 공간 상태를 함께 유지하도록 요구한다.
- 화면·근거: 문제 재구성 C62, [P22 ST-AudioQA Table 1](https://arxiv.org/html/2606.14141v1). 두 음원의 시간별 위치와 질문의 참조 시점을 대응시킨다. 한 음원의 속성, 두 음원 식별, 시간 조건 관계 중 마지막 질문을 주목하게 한다.
- 설명 순서: “각 순간의 방향이 맞아도 어느 음원이 이동했는지 바뀌면 답이 틀립니다. 여기서는 같은 음원의 시간별 상태를 관계 질문까지 연결해야 합니다.”
- 경계·부록: 설명용 궤적과 실제 모델 예측을 구분한다. 통제된 한·두 음원 합성 장면을 밀집한 현실 장면이나 연속 대화로 확대하지 않는다.
- 다음 연결: “이런 질문을 위해 모델이 시간별로 어떤 표현을 유지하는지 보겠습니다.”

### S63. ST-AudioLM의 의미·궤적 표현

- 청중 질문: 전체 클립을 요약한 공간 표현에 어떤 시간별 정보를 더해야 움직임 질문에 답할 수 있는가?
- 남길 한 문장: ST-AudioLM은 사건 의미와 시간별 공간 상태를 담은 표현을 언어 모델에 연결한다.
- 화면·근거: 방법 [P22 Fig. 1](https://arxiv.org/html/2606.14141v1). 시간별 공간 표현과 클립 의미가 언어 입력으로 이어지는 경로를 중심으로 읽는다. 표현이 시간축을 유지하는 위치를 강조하고 내부 블록 전체를 설명하지 않는다.
- 설명 순서: “먼저 사건이 무엇인지 나타내는 정보와 시간별 위치 정보를 구분하겠습니다. 두 정보를 언어 입력으로 전달하면 앞 장의 시간 조건 질문을 학습할 수 있습니다.”
- 경계·부록: Fig. 1을 문제의식 그림으로 부르지 않는다. 정적 인코더의 구간별 적용과 궤적 지도 학습을 같은 방법으로 그리지 않으며 encoder Table 3은 부록에 둔다.
- 다음 연결: “공간 표현에 시간을 남기는 효과가 조합 QA에서도 나타났는지 확인하겠습니다.”

### S64. 조합 QA에서 남는 움직임 난도

- 청중 질문: 시간 정보를 추가하면 이동 조건 관계와 두 음원의 궤적 비교까지 쉽게 풀리는가?
- 남길 한 문장: ST-AudioLM은 조합 QA 평균을 개선했지만 이동·궤적 관계의 점수는 시간 관계보다 낮다.
- 화면·근거: 결과 [P22 Table 5](https://arxiv.org/html/2606.14141v1). Spatial-AST-FOA+OLMo2와 ST-AudioLM의 평균 63.3/67.5를 비교한다. ST-AudioLM의 시간 관계 86.0, 이동 조건 관계 55.8, 궤적 관계 60.6을 함께 읽는다.
- 설명 순서: “같은 FOA 계열 비교에서 평균은 높아집니다. 다만 평균을 펼치면 이동하는 음원들 사이의 관계 질문에 여전히 큰 어려움이 남습니다.”
- 경계·부록: controlled-answer accuracy이며 BAT와는 입력 렌더링이 다르다. 기본·두 음원 QA Table 4와 실제 녹음의 encoder 평가는 별도 부록으로 분리한다.
- 다음 연결: “시간의 다른 축인 사건 순서로 옮겨, 위치가 고정돼도 순서가 답을 바꾸는 경우를 보겠습니다.”

### S65. 사건 순서와 위치만 바꾼 검색 후보

- 청중 질문: 같은 두 소리라도 발생 순서나 각 소리의 위치가 달라지면 설명문과의 대응을 구별할 수 있는가?
- 남길 한 문장: CoSTALA는 두 사건의 순서와 공간 속성을 바꾼 후보를 구별하도록 표현을 학습한다.
- 화면·근거: 문제 재구성 C65, [P23 §2.1](https://arxiv.org/html/2608.24374v1). 기준 사건열과 temporal negative, spatial negative를 동일 시간축에서 비교한다. 움직이는 궤적은 그리지 않고 각 사건의 방향과 발생 순서만 바꾼다.
- 설명 순서: “앞 장의 연속 이동과 다른 분기입니다. 위치가 고정된 두 사건도 순서를 뒤집으면 문장과의 대응이 달라지므로 이 차이를 검색 문제로 만들 수 있습니다.”
- 경계·부록: 겹치지 않는 두 합성 FOA 사건과 8방향의 범위를 유지한다. Fig. 1은 방법이며 자유형 QA의 성공 사례로 쓰지 않는다.
- 다음 연결: “사건별 학습 항을 더한 뒤, 이런 후보를 찾는 검색 성능이 달라졌는지 보겠습니다.”

### S66. 사건별 정렬의 검색 효과와 이해 확인

- 청중 질문: 사건별 정렬을 더하면 검색이 개선되는가, 그리고 그 결과로 연속 이동 이해까지 말할 수 있는가?
- 남길 한 문장: CoSTALA의 전체 loss는 이 합성 사건열 검색을 개선하지만 다른 시간 과제에는 별도 검증이 필요하다.
- 화면·근거: 결과 [P23 Table 2](https://arxiv.org/html/2608.24374v1). contrastive-only와 전체 loss의 global Text-to-Audio R@1 5.84/8.10을 선택한다. 평가 표현은 §3.1의 E_global과 T_st로 명시한다.
- 설명 순서: “사건별 정렬과 일관성 학습을 짧게 설명한 뒤 검색 결과를 읽겠습니다. 이어 ‘순서 검색 성공이 움직이는 음원의 추적 성공을 뜻할까요?’라고 확인하고 평가 범위로 답을 회수합니다.”
- 경계·부록: Fig. 2의 E_st를 직접 평가한 표라고 부르지 않는다. 원 segment duration 사용과 semantic-only 결과의 한계는 부록에 남긴다.
- 다음 연결: “서로 다른 성공 사례를 살펴봤습니다. 이제 답변의 정답률이 얼마나 청각 근거에 의존하는지 따져보겠습니다.”
