# 공간 소리를 듣고 판단하는 모델: 발표 흐름 재설계안

작성: 2026-09-09

이 문서는 다음 개정의 설계안이다. 현재 `slides.md`와 PDF는 기존 42장 그대로이며, 아래의 새 번호는 아직 적용하지 않았다. 기존 `ACADEMIC_STRUCTURE.md`는 현재 덱의 설명으로 유지한다.

## 1. 발표의 목표와 범위

중심 질문: **모델은 소리를 듣고, 무엇이 어디에서 어떻게 일어나는지 판단할 수 있는가?**

공간 오디오의 지각, 표현 학습, 장면 이해, 시공간 추론을 다룬다. 언어 모델은 판단 결과를 읽는 한 방식이다. 위치 추정이나 SELD를 언어 모델의 미완성 단계로 취급하지 않는다.

음원 생성, 재생, 렌더링, 장치 설계, 로봇 제어는 독립 주제로 다루지 않는다. 시뮬레이션은 학습·평가 데이터의 조건을 설명할 때 사용한다. 분리나 시각 정보도 청각 판단에 기여하는 경우에만 보조적으로 언급한다. 음질 개선이나 영상 이해 자체로 범위를 넓히지 않는다.

청중은 기본적인 머신러닝을 알고 있지만 공간 음향에는 익숙하지 않은 대학원 세미나 청중으로 가정한다. 발표 시간이 확정되지 않았으므로 **본문 32장, 약 40분**을 작업 기준으로 잡는다. 부록과 연구 제안 토의 시간은 포함하지 않는다. 이 숫자는 제작 전 조정 가능한 설계값이다.

## 2. 설명의 중심 장면

설명용 장면: 왼쪽에는 말소리, 오른쪽에는 알람이 있다. 모델에게 “알람이 어느 쪽에서 울리는가?”라고 묻는다.

- 도입에서는 소리 종류의 목록과 음원별 위치를 연결하는 판단의 차이를 보여준다.
- 물리 설명에서는 알람 하나만 남겨 경로차와 시간차를 설명한다. 실제의 다중 음원 장면과 단일 직접음 근사를 명시적으로 구분한다.
- 배열 변경 장면에서는 음원, 배열 중심, 기준 좌표계를 고정하고 마이크 배치만 바꾼다.
- 공간 판단 절에서는 두 소리의 위치를 맞바꾼 장면을 비교한다.
- 동적 판단 절에서는 알람 발생 장치가 이동한다고 설정하고, 동일한 소리 종류라도 궤적이 다를 수 있음을 보여준다.
- 마지막에는 최초 질문과 확장된 질문을 다시 제시하고, 문헌이 보여준 능력과 평가 범위를 구분한다.

이 장면은 설명을 위한 사고실험이다. 실제 모델의 실패·성공 사례로 표시하지 않는다. 오디오를 제작하거나 재생할 경우 동일 소스, 위치, 이동, 잡음 등의 조건을 별도로 정의해야 한다. 이 설계 단계에서는 음원이나 그림을 새로 만들지 않는다.

기초 설명의 정확성: 마이크 두 개의 지연 하나가 3차원 방향을 유일하게 결정한다고 설명하지 않는다. 단일 채널에는 공간 정보가 전혀 없다고 단정하지 않는다. 크기만으로 거리가 정해진다고 설명하지 않는다. HRTF와 FOA의 세부는 해당 입력을 사용하는 연구가 등장할 때 설명한다. PHAT 유도와 신호처리 방법의 전체 분류는 부록으로 둔다.

BAT은 언어 인터페이스의 연결 사례로 사용하며 성능을 주장하려면 별도 근거를 제시한다. 여러 연구가 모두 동일한 모노 인코더·기하 입력을 갖는다고 그리지 않는다. DSpAST의 요인 분리, OWL의 기하 지도 학습을 PhaseCoder·Spatial-Omni의 모듈 추가 방식과 구분한다. OWL의 깊이·RIR 지도는 추론 입력이 아니다.

### G. 결론: 32장

제목안: **처음의 알람 질문에 돌아오면**

최초의 장면과 질문을 다시 제시한다. 아래는 한 슬라이드에 세부 수치를 모두 채우기 위한 표가 아니라 결론을 작성할 기준이다.

## 8. 다음 제작에서 지킬 조건

1. 도입 8장을 읽는 데 특정 논문이나 Transformer 구조 지식이 필요하지 않아야 한다.
2. 각 중심 사례는 먼저 관측·과제의 어려움을 보여주고, 설계 선택과 실험 증거로 그 질문을 회수한다.
3. 본문의 주요 성과 주장은 최소 하나의 원문 결과와 평가 조건을 갖는다. 구조도나 출력 예시만으로 성능을 주장하지 않는다.
4. 논문마다 문제 그림을 기계적으로 한 장씩 추가하지 않는다. 공통 문제는 함께 설명하되 각 연구가 다루는 차이는 분명히 남긴다.
5. 그림은 그림 번호가 아니라 설명 역할로 선택한다. 예를 들어 ST-AudioLM Fig. 1은 문제 그림이 아니다.
6. 입력 형식, 학습·고정 모듈, 데이터 분할이 다른 모델의 숫자를 하나의 우열 순위로 만들지 않는다.
7. 최근 논문을 소개할 때 원고 버전과 공개·출판 상태를 표시한다. 이 설계안은 선택적 최근 연구 리뷰이며 포괄적 문헌고찰을 주장하지 않는다.
8. 32장의 결론은 특정한 새 아키텍처의 필요성을 이미 입증했다고 주장하지 않는다.
9. 본문에 남길 그림·결과의 가독성이 부족하면 상세를 부록으로 옮긴다. 문제와 증거를 제거하고 구조도만 남기는 축약은 피한다.
10. 이 설계안만으로 그림의 확보나 슬라이드의 완성을 주장하지 않는다. 실제 개정 때 전체 렌더링을 다시 확인한다.
